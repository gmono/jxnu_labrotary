# 网站原型构建框架
## 起源
由使用Bootstrap写Jxnu图片获取器的舒爽感受得到启发

一般来说，写原型网站与写产品不同，不需要高性能和架构，只需要快准狠，于是大略有以下几个要求
1. 快速构建，实现功能，这就包括快速创建项目，随时修改，使用实时预览设计网页，每个组件都可以单独在浏览器中查看编辑修改（如同传统页面一样）
2. 分页。也就是几个不同的page分割在不同的文件中，需要时自动加载，或是一次性载入并不重要，重要的是完善的作用域划分，包括基本的CSS作用域隔离和更高难度的JS作用域隔离，最好是可以直接在子页中使用JQ
3. 自动得到节点。根本不怕冗余，就怕慢，直接自动通过生成代码的方式得到子页中存在的一切声明了ID或class的节点和节点集合，使用时直接操作不需要getElementById或通过JQ获取
4. 顺畅的逻辑流而非完善的框架。原型实现不需要高性能，高规范。因此传统的路由策略不应使用，而应该以尽量简单的，与传统网页中的逻辑流控制类似的方式控制页面。例如
    * 基于锚链接的分页和跳转
    * 基于容器和a标签target的，类似iframe的分页和跳转
    * 直接了当的全局和分层数据Store
    * 整体0配置
    * 直接了当的参数/属性/事件传递，子组件的对外暴露
    * 简单的嵌套页面分发，Minix/Fragment
    * 复杂锚链接，锚路由，即通过锚链接给某个标签加上class或取消class等，例如加上通用的active类
5. 0配置的数据获取和测试数据（mock）：
    * 自动从服务器获取数据
    * 自动从服务器更新数据，根据要求自动从客户端上传数据到服务器
    * 让所有客户端的操作都是本地操作，屏蔽远端
    * 自动按层次注入数据容器并保持同步
6. 优秀的代码提示。无论通过什么方法，甚至损失性能的方法，也一定要提供足够的代码提示功能，否则快速开发无法进行
7. 使用全局库进行开发，例如Bootstrap等，但子页引入的CSS可以选择进行处理(后期事务)
8. 使用html语义扩展描述页面逻辑，而非使用代码和事件,允许用户自己进行html语义扩展
9. 不需要使用固定的套件比如Webpack，Brunch等进行项目构建，不需要使用Node.js作为基础和依赖管理（但可能用于工具的编写），用户不需要通过统一的格式和流程例如在package.json中注册包，或在配置文件中注册插件等做扩展
10. 即写即运行，宁愿浏览器处理编译，也不进行本地编译，浪费时间，不使用gulp等固定的task工具，避免任何框架化操作
## 工具链
本实验统一使用brunch工具链 需要使用node提供的库的部分写在app目录，修改后使用brunch build 一次性编译即可（自动输出为public目录的app.js文件）

**本产品使用typescript编写 请勿手动修改js文件**
## 设计和进度
当前进度：测试JQ插件基本可用 插件中没有使用JQ，但使用了window.onload和document的创建节点等功能 目前工作正常 域封闭性正常 CSS封闭性正常 JS作用域封闭基本正常其他有待测试

## 目前工作重点
1. 编写需要代理的Document的Proxy对象和Window的Proxy对象,设法将代理对象从loadPage函数中分离出来
2. 测试组件内引入JQ时会不会出现越界
3. Window的Proxy 监视逻辑尚不完善
4. 测试使用Proxy 的polyfill时的效果，以及同时使用ES5编译时能不能在低版本浏览器工作
5. 将之前临时写在app目录里的lib.ts 声明文件规范化并和public中的声明分开（例如对Window类的追加声明）
6. 给组件文件（page）内添加语法提示（例如props和msghub等，考虑通过只在测试时生效的专用声明文件实现
7. 添加容器型slot（modsign无关）支持
8. 添加组件声明式引用,即将
    ```html
    <component src="./page1.html"></component>
    ```
    转换为
    ```html
    <div id="__component_1"></div>
    <script>
    loadFile(document.getElementById("__component_1"),"./page1.html")
    </script>
    ```
9. 添加功能型slot支持（modsign一致化，通过loadFile的自定义modsign实现），其可以起到style容器的功能
10. msghub添加“组件功能对象”功能，即通过指定id得到一个组件向外暴露的“接口对象”，其中包含暴露的函数和属性，可以通过这个方法而不是message的方式调用其他组件的功能，例如在某个Screen组件上显示一串文本或一个图片
11. 进一步的，提供“组件功能对象”的接口划分功能，即如果几个组件暴露的对象提供了同一种接口，则另一个组件可以同时获取它们并一次性调用（通过自动生成的Proxy对象），比如同时在所有Screen上显示图片和文字
## 修改的依赖
>由于部分依赖特别是Posthtml中提供的功能比如match等不完整，遍历方式局限，修改方式局限使中间件功能不能完成 因此重写了部分依赖

> postcss使用了 fs和path模块 经过注释后可用，但使用yarn 重新载入依赖时需要手动修改才能编译app.js

postcss中屏蔽了所有fs和path模块的require 不使用时没有错误
posthtml 添加了附加的api用于复杂功能

##目录结构

2. public保存测试网页，test.ts（loadPage）等纯浏览器端的库（避免重编译）
