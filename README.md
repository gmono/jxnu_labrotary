# 网站原型构建框架
## 起源
由使用Bootstrap写Jxnu图片获取器的舒爽感受得到启发

一般来说，写原型网站与写产品不同，不需要高性能和架构，只需要快准狠，于是大略有以下几个要求
1. 快速构建，实现功能，这就包括快速创建项目，随时修改，使用实时预览设计网页，每个组件都可以单独在浏览器中查看编辑修改（如同传统页面一样）
2. 分页。也就是几个不同的page分割在不同的文件中，需要时自动加载，或是一次性载入并不重要，重要的是完善的作用域划分，包括基本的CSS作用域隔离和更高难度的JS作用域隔离，最好是可以直接在子页中使用JQ
3. 自动得到节点。根本不怕冗余，就怕慢，直接自动通过生成代码的方式得到子页中存在的一切声明了ID或class的节点和节点集合，使用时直接操作不需要getElementById或通过JQ获取
4. 顺畅的逻辑流而非完善的框架。原型实现不需要高性能，高规范。因此传统的路由策略不应使用，而应该以尽量简单的，与传统网页中的逻辑流控制类似的方式控制页面。例如
    * 基于锚链接的分页和跳转
    * 基于容器和a标签target的，类似iframe的分页和跳转
    * 直接了当的全局和分层数据Store
    * 整体0配置
    * 直接了当的参数/属性/事件传递，子组件的对外暴露
    * 简单的嵌套页面分发，Minix/Fragment
    * 复杂锚链接，锚路由，即通过锚链接给某个标签加上class或取消class等，例如加上通用的active类
5. 0配置的数据获取和测试数据（mock）：
    * 自动从服务器获取数据
    * 自动从服务器更新数据，根据要求自动从客户端上传数据到服务器
    * 让所有客户端的操作都是本地操作，屏蔽远端
    * 自动按层次注入数据容器并保持同步
6. 优秀的代码提示。无论通过什么方法，甚至损失性能的方法，也一定要提供足够的代码提示功能，否则快速开发无法进行
7. 使用全局库进行开发，例如Bootstrap等，但子页引入的CSS可以选择进行处理(后期事务)
8. 使用html语义扩展描述页面逻辑，而非使用代码和事件,允许用户自己进行html语义扩展
9. 不需要使用固定的套件比如Webpack，Brunch等进行项目构建，不需要使用Node.js作为基础和依赖管理（但可能用于工具的编写），用户不需要通过统一的格式和流程例如在package.json中注册包，或在配置文件中注册插件等做扩展
10. 即写即运行，宁愿浏览器处理编译，也不进行本地编译，浪费时间，不使用gulp等固定的task工具，避免任何框架化操作
## 设计和进度
当前进度：子页加载器和容器/链接跳转路由
子页功能考虑用css-modules实现
这样只支持类选择器
还可以通过另附属性实现，但这样就需要解析css，可以通过postcss插件形式实现
html部分考虑使用pug或html解析器解析

## 修改的依赖
postcss中屏蔽了所有fs和path模块的require 不使用时没有错误
posthtml 添加了附加的api用于复杂功能
